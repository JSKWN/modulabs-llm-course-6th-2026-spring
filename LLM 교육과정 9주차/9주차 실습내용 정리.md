## 핵심 개념 상세 정리

### 9-1. Adaptive RAG 개념 — 쿼리 복잡도별 동적 라우팅

논문: [Adaptive-RAG (2024)](https://arxiv.org/pdf/2403.14403)

기존 RAG는 모든 질문에 동일한 검색 절차를 적용 → 단순 질의에는 비효율적이고, 복잡한 질의에는 불충분.
Adaptive RAG는 질문 복잡도를 분류하여 경로를 동적으로 결정함.

| 경로 | 대상 | 예시 |
|---|---|---|
| direct | LLM 자체 지식으로 답변 가능 | "파이썬 데코레이터란?" |
| rag | 내부 문서/특정 도메인 지식 필요 | "우리 회사 연차 규정은?" |
| web_search | 최신/실시간 정보 필요 | "오늘 날씨는?" |
| multihop | 여러 단계 추론 필요 | "봉준호 2019년 영화의 음악감독 출생연도는?" |

> 실무: 예전에는 T5 등을 fine-tuning하여 쿼리 분류를 했으나, 현재는 GPT/Qwen 등 모델 성능이 우수하여 fine-tuning 없이도 가능

### 9-2. 쿼리 분석 — QueryAnalysis & with_structured_output

- `BaseModel`로 출력 스키마 정의 → `llm.with_structured_output()`로 형식 강제
- `Literal` 타입으로 라우팅 경로를 제한 (direct / rag / web_search)

```python
class QueryAnalysis(BaseModel):
    query: str = Field(description='원본 쿼리')
    route: Literal["direct", "rag", "web_search"] = Field(
        description="라우팅 경로"
    )
    confidence: float = Field(description='분류 신뢰도(0.0~1.0)', ge=0.0, le=1.0)
    reasoning: str = Field(description='분류 이유')

response = llm.with_structured_output(QueryAnalysis).invoke([
    SystemMessage(content=system_prompt),
    HumanMessage(content=query)
])
```

> 실무: `llm.invoke()`만 쓰면 "direct, direct 쿼리입니다..." 같은 자유 형식 → 파싱 어려움. structured output으로 형식 강제하면 바로 사용 가능

### 9-3. Fallback & 라우팅 엔진 — 신뢰도·가중치 기반 폴백

- 신뢰도(confidence)가 임계치 미만이면 fallback 경로(rag)로 전환
- `@dataclass`로 설정(RoutingConfig)과 로그(RoutingLog) 관리

```python
@dataclass
class RoutingConfig:
    confidence_threshold: float = 0.7
    fallback_route: str = 'rag'
    enable_logging: bool = True

class RoutingEngine:
    def route(self, analysis: QueryAnalysis) -> str:
        if analysis.confidence < self.config.confidence_threshold:
            return self.config.fallback_route  # fallback
        return analysis.route
```

#### 가중치 기반 라우팅

- `AdvancedRoutingConfig`에 `route_weights` 딕셔너리 추가
- `weighted_score = confidence * weight` → 임계치 미만이면 fallback

| 경로 | 가중치 | 의미 |
|---|---|---|
| direct | 1.0 | 높은 신뢰도 요구 |
| rag | 0.8 | 중간 신뢰도 |
| web_search | 0.6 | 낮은 가중치(외부 의존) |

### 9-4. RouteHandler — ABC 핸들러 패턴

- 추상 클래스(`ABC`)로 공통 인터페이스 정의 → Direct / RAG / WebSearch 핸들러 구현
- `handlers` 딕셔너리로 라우팅 결과에 따라 핸들러 자동 선택

```python
class RouteHandler(ABC):
    @abstractmethod
    def handle(self, query: str) -> str:
        pass

handlers = {
    'direct': DirectHandler(),
    'rag': RAGHandler(),
    'web_search': WebSearchHandler()
}
result = handlers[route].handle(query)
```

### 9-5. LangGraph 기반 Adaptive RAG 워크플로

- `AdaptiveRAGState`: query, route, confidence, response, documents, search_results 채널
- `query_analyzer_node` → `route_query` 조건부 분기 → direct / rag / web_search 노드

```
START → query_analyzer → route_query 분기
                         ├─ direct_answer ──┐
                         ├─ rag_search ─────┤→ END
                         └─ web_search ─────┘
```

- Finalize 노드 추가 시: 모든 경로가 finalize를 거쳐 END로 이동 → 처리 경로, 참고문서 수, 타임스탬프 집계

### 9-6. Multi-hop 추론 — IRCoT think-retrieve 루프

- `_Think` 모델: `next_sub_query`(추가 검색 필요) / `can_answer`(답변 가능) 판단
- IRCoT(Interleaving Retrieval with Chain-of-Thought) 패턴

```
classify → multihop → think ──→ can_answer? ──→ finalize → END
                        ↑           │ no
                        └── retrieve ←┘
```

```python
class _Think(BaseModel):
    next_sub_query: Optional[str] = Field(None,
        description='더 검색이 필요하면 다음 sub-query, 충분하면 None')
    can_answer: bool = Field(description='현재 정보로 답변 가능한가?')
```

- 중복 sub_query 감지: 이미 검색한 쿼리면 종료
- `max_hops`로 무한루프 방지

> 실무: GraphRAG는 DB를 그래프화하여 multi-hop을 처리. IRCoT는 LLM이 중간에 retriever를 끼워 넣어 추론하는 방식

### 9-7. Self-RAG 개념 — 자가 평가 기반 검색-생성 루프

논문: [Self-RAG (2023)](https://arxiv.org/pdf/2310.11511)

| 방식 | 핵심 차이 |
|---|---|
| Adaptive RAG | 쿼리 → 검색 수행 여부 판단(입력 기반) |
| Self-RAG | retrieved 문서에 대해 답변 유용성 등을 판단하여 루프(출력 기반) |

원논문에서는 reflection token을 fine-tuning하여 학습하지만, 구현체에서는 LLM-as-judge 패턴(`with_structured_output`)으로 대체.

#### SelfRAGState 설계

```python
class SelfRAGState(TypedDict):
    question: str              # 사용자 질문 (불변)
    rewritten_question: str    # 재작성된 쿼리 (C-RAG 개념)
    documents: List[Document]  # 검색된 문서
    filtered_documents: List[Document]  # 관련성 필터링된 문서
    generation: str            # LLM 생성 답변
    relevance_grades: List[str]  # 문서별 관련 여부
    hallucination_score: str   # 환각 여부
    usefulness_score: int      # 1-5점 유용성
    relevance_retries: int     # 재검색 횟수
    generation_retries: int    # 재생성 횟수
    max_tries: int             # 무한루프 방지
```

### 9-8. 문서 관련성 평가 & 조건부 재검색

- `_Relevance` 모델: 문서가 질문과 관련 있는지 yes/no 판단
- `grade_and_filter_node`: 각 문서별 관련성 평가 → yes 문서만 `filtered_documents`에 유지

```python
class _Relevance(BaseModel):
    binary: Literal['yes', 'no'] = Field(
        description='문서가 질문과 관련이 있는지')

def grade_and_filter_node(state) -> dict:
    grades, keep = [], []
    for d in state['documents']:
        g = relevance_grader.invoke(msg).binary
        grades.append(g)
        if g == 'yes':
            keep.append(d)
    return {'relevance_grades': grades, 'filtered_documents': keep}
```

- `relevance_router`: 필터링된 문서가 있으면 generate, 없으면 retrieve/rewrite_query

### 9-9. 쿼리 재작성 — rewrite_query_node

- 검색 실패 시 동의어/구체화로 쿼리를 바꿔 다시 검색하는 폴백 패턴
- `retrieve_aware_node`: `rewritten_question`이 있으면 이를 사용, 없으면 원본 `question` 사용

```python
def rewrite_query_node(state) -> dict:
    msg = REWRITE_PROMPT.format_messages(question=state['question'])
    new_q = llm.invoke(msg).content.strip()
    return {'rewritten_question': new_q, 'relevance_retries': state['relevance_retries'] + 1}
```

- `MAX_QUERY_REWRITE` 카운터: 재작성 횟수 초과 시 `give_up_node`로 이동 → 무한루프 방지

> 실무: 같은 쿼리를 같은 모델에 던지면 비슷한 답변 → 재작성으로 검색 다양성 확보. 원래 Self-RAG 논문에는 없고 C-RAG에서 도입된 개념

### 9-10. 환각 평가 — grade_hallucination

- `_Hallucination` 모델: 답변이 문서에 근거하는지 yes(환각)/no(근거 있음) 판단
- 환각이면 재생성, `generation_retries` 카운터로 재생성 횟수 제한

```python
class _Hallucination(BaseModel):
    binary: Literal['yes', 'no'] = Field(
        description='답변이 환각인지 (yes=문서 밖 정보, no=근거 있음)')

def hallucination_router(state) -> str:
    if state['generation_retries'] >= 2:
        return 'usefulness'
    return 'generate' if state['hallucination_score'] == 'yes' else 'usefulness'
```

> 실무: 재생성 시 temperature를 0.7로 높이거나, "이전 답변은 환각이었습니다" 프롬프트를 추가하여 다양성 확보

### 9-11. 유용성 평가 — grade_usefulness

- `_Usefulness` 모델: 답변이 질문에 적합한지 1-5점 평가
- 점수별 라우팅: 5점 → END, 3-4점 → 재생성, 1-2점 → 재검색

```python
class _Usefulness(BaseModel):
    score: int = Field(description='답변의 유용성 1-5점', ge=1, le=5)

def usefulness_router(state) -> str:
    if state['generation_retries'] >= MAX_GENERATION_RETRIES:
        return 'end'
    score = state['usefulness_score']
    if score == 5: return 'end'
    elif score <= 3: return 'generate'
    else: return 'retrieve'
```

> 실무: 유용성 점수가 계속 4점에 머무르면 max_retries에 도달할 때까지 루프. 안전 라우터에서 `generation_retries`와 `relevance_retries` 모두 체크해야 함

### 9-12. C-RAG & Knowledge Refine — 3등급 분류 + 문장 단위 필터링

#### C-RAG (Corrective RAG)

기존 binary(yes/no)를 3등급으로 확장:

| 등급 | 점수 범위 | 의미 |
|---|---|---|
| correct | 0.8 이상 | 내부 지식으로 충분 |
| ambiguous | 0.4~0.8 | 외부 검색 필요 |
| incorrect | 0.4 미만 | 부적합 |

```python
class _CragGrade(BaseModel):
    grade: Literal['correct', 'ambiguous', 'incorrect']
    score: float = Field(ge=0.0, le=1.0)
```

#### Knowledge Refine

- 문서를 문장 단위로 분해 → 각 문장의 질문 관련성 평가 → 관련 문장만 재조립
- 기존 문서 단위 필터링보다 세밀한 컨텍스트 정제

```python
def knowledge_refine_node(state) -> dict:
    for doc in docs:
        strips = doc.page_content.split(".")
        kept = [s for s in strips if strip_grader.invoke(...).relevant]
        if kept:
            refined.append(Document(page_content='. '.join(kept)))
    return {'filtered_documents': refined}
```

## 코드 흐름 정리

```
[1차시: Adaptive RAG]
query → QueryAnalysis(with_structured_output) → RoutingEngine(confidence 체크)
    │
    ├── direct → DirectHandler
    ├── rag    → RAGHandler
    └── web    → WebSearchHandler
    │
    └── LangGraph 버전: query_analyzer → route_query 분기 → 노드 → END

[2차시: Multi-hop & 에러 처리]
query → classify(4경로) → direct / rag(FAISS) / web(FakeWebSearch) → finalize → END
                        └→ multihop → think ←→ retrieve (IRCoT 루프) → finalize → END
    │
    └── safe_classify_node: try/except + CLASSIFY_COUNTER

[3차시: Self-RAG]
retrieve → grade_and_filter → relevance_router
    │                           ├── yes 문서 있음 → generate → grade_hallucination → END
    │                           └── 없음 → rewrite_query → retrieve (루프)
    └── give_up_node (MAX_QUERY_REWRITE 초과 시)

[4차시: Self-RAG 완성 & C-RAG]
retrieve → grade_relevance → router → generate → grade_hallucination → router → grade_usefulness → router → END
    ↑       rewrite_query ←┘           ↑           generate ←┘                     ↑ retrieve (1-2점)
    └───────────────────────────────────────────────────────────────────── generate (3-4점)
    │
    └── C-RAG: correct/ambiguous/incorrect 3등급
    └── Knowledge Refine: 문장 분해 → 관련성 필터 → 재조립
```

### 주요 함수 I/O

| 함수 | 입력 | 출력 |
|---|---|---|
| `classify_node(state)` | AdaptiveState(query) | `{'route': 'direct'/'rag'/'web'/'multihop'}` |
| `think_node(state)` | AdaptiveState(query, retrieved) | `{'hop_count': N, 'sub_queries': [...], 'answer': ...}` |
| `grade_and_filter_node(state)` | SelfRAGState(question, documents) | `{'relevance_grades': [...], 'filtered_documents': [...]}` |
| `grade_hallucination_node(state)` | SelfRAGState(generation, filtered_documents) | `{'hallucination_score': 'yes'/'no'}` |
| `grade_usefulness_node(state)` | SelfRAGState(question, generation) | `{'usefulness_score': 1-5}` |
| `rewrite_query_node(state)` | SelfRAGState(question) | `{'rewritten_question': '...', 'relevance_retries': N}` |
| `crag_grade_node(state)` | SelfRAGState(question, documents) | `{'crag_grade': '...', 'crag_score': 0.85}` |
| `knowledge_refine_node(state)` | SelfRAGState(documents/filtered_documents) | `{'filtered_documents': [Document(문장 단위)]}` |

### Self-RAG 평가 모델 비교

| 모델 | 역할 | 출력 | 후속 동작 |
|---|---|---|---|
| `_Relevance` | 문서 관련성 | yes/no | yes → 유지, no → 필터 |
| `_Hallucination` | 답변 근거 확인 | yes(환각)/no(근거) | yes → 재생성 |
| `_Usefulness` | 답변 유용성 | 1-5점 | 5 → END, 3-4 → 재생성, 1-2 → 재검색 |
| `_CragGrade` | C-RAG 3등급 | correct/ambiguous/incorrect + score | grade별 후속 처리 분기 |
| `_StripGrade` | 문장 관련성 | relevant(bool) | True → 유지, False → 제거 |

## 고려사항 & 질문 모음

1. **노드 반환 타입 주의**: `fallback_node`에서 문자열만 반환하면 `InvalidUpdateError` 발생. 노드는 반드시 `dict`를 반환해야 함 (`return {'response': '...'}` 형태).

2. **무한루프 방지**: Self-RAG에서 쿼리 재작성-재검색-관련성 평가 루프는 관련 문서가 아예 없으면 무한루프 발생. `MAX_QUERY_REWRITE`, `max_retries`, `generation_retries` 등 카운터 필수.

3. **유용성 평가 루프 이슈**: `usefulness_score`가 4점에 머무르면 `max_retries`에 도달할 때까지 계속 재생성. 5점이 아닌 4점 이상을 통과 기준으로 하는 것도 고려할 만함.

4. **컨텍스트 구성 전략**: 단순 `'\n'.join()` 외에 글자 수 축소, re-ranking, 문장 단위 필터링(Knowledge Refine) 등 다양한 접근 가능.

5. **Adaptive RAG vs Self-RAG vs C-RAG**: Adaptive는 입력(쿼리) 기반 라우팅, Self-RAG는 출력(답변) 기반 평가 루프, C-RAG는 binary를 3등급으로 확장하고 문장 단위 정제를 추가. 실제 시스템에서는 세 가지를 조합하여 사용.

6. **그래프 전체 노드 실행 횟수 제한**: LangGraph는 전체 노드 실행 횟수를 50 또는 100으로 제한 가능. 복잡한 평가 루프에서는 이 상한에 걸릴 수 있으므로 설정 필요.
