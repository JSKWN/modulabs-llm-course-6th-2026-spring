## 핵심 개념 상세 정리

### 11-1. CLIP: 이미지·텍스트 joint embedding

OpenAI가 4억 개 이미지·텍스트 쌍으로 학습한 모델. 이미지와 텍스트를 같은 벡터 공간에 매핑해, 별도 fine-tuning 없이 분류·검색이 가능함(zero-shot).

#### zero-shot 분류 원리

- 이미지 임베딩과 여러 후보 텍스트 임베딩의 유사도를 비교해 가장 가까운 텍스트를 선택
- `logits_per_image.softmax()`로 후보별 확률 산출

```python
candidates = ['a red square and a blue ellipse', 'a revenue bar chart', 'a KPI dashboard', 'a photo of dog']
inputs = processor(text=candidates, images=img, return_tensors='pt', padding=True)
probs = model(**inputs).logits_per_image.softmax(dim=1)[0]  # 후보별 확률
```

> 실무: vision/text 인코더의 pooler 출력을 `visual_projection`으로 512차원 공유 공간에 투영함. 이 공유 공간 덕분에 이미지와 텍스트를 직접 비교 가능

### 11-2. 멀티모달 RAG의 3대 구성요소

멀티모달 RAG는 세 요소가 모두 있어야 동작함.

| 구성요소 | 역할 | 예시 |
|---|---|---|
| 멀티모달 인코더 | 이미지·텍스트·표를 한 벡터 공간에 매핑 | CLIP, ColPali |
| 리트리벌 인덱스 | 멀티모달·멀티벡터 쿼리 지원 벡터 DB | Qdrant, Vespa (FAISS·Chroma는 부족) |
| 멀티모달 제네레이터 | 텍스트+이미지를 받아 답변 생성 | VLM (Vision LLM) |

### 11-3. 멀티모달 RAG의 3가지 접근

| 접근 | 방식 | 장점 | 단점 |
|---|---|---|---|
| 1. Caption-then-RAG | 이미지를 VLM으로 캡션 생성 후 텍스트 RAG | 단순, 기존 RAG 재사용 | 정보 손실 큼, VLM 비용 |
| 2. Separate-Index | 텍스트·이미지를 각각 임베딩해 분리 인덱싱 | 모달리티별 최적화 | 두 인덱스 관리, 결과 병합 난이도 |
| 3. Unified Visual | 페이지를 통째로 이미지로 ViT 임베딩(ColPali) | OCR·파싱 불필요, 시각 정보 보존 | 벡터 수 폭증 |

> 실무: ColPali는 PaliGemma(비전·언어 모델)와 ColBERT의 late interaction을 결합. PDF 페이지를 이미지로 인덱싱해 표·레이아웃 손실을 막음

### 11-4. 멀티모달 표현 학습 (Contrastive Learning)

이미지·텍스트를 같은 공간의 가까운 점에 놓도록 학습하는 원리.

- Joint Embedding: 별도 인코더의 출력을 하나의 공유 공간에 배치
- Mutual Information(MI): 두 모달리티가 공유하는 정보량. 직접 계산이 불가능해 변분 하한(ELBO)을 대신 최대화
- Contrastive Learning: 실제 쌍(positive)은 가깝게, 무관한 쌍(negative)은 멀게. 배치 내 다른 샘플을 negative로 활용해 레이블 없이 대규모 학습
- InfoNCE / Sigmoid Loss: CLIP은 softmax 기반 InfoNCE(배치 클수록 유리, 메모리 부담). SigLIP은 각 쌍을 독립 이진 분류로 처리해 배치 의존성을 줄인 개선판

### 11-6. CLIP 인코딩 함수와 코사인 유사도

```python
def encode_image_clip(image) -> np.ndarray:   # 이미지 → 정규화된 512차원 임베딩
    inputs = processor(images=image, return_tensors='pt').to(DEVICE)
    feat = model.get_image_features(**inputs)[0].detach().cpu().numpy()
    return feat / np.linalg.norm(feat)        # L2 정규화
```

- 이미지·텍스트 인코딩을 함수로 캡슐화(`encode_image_clip`, `encode_text_clip`)
- 코사인 유사도는 `dot(a, b) / (norm(a)*norm(b))`. 임베딩을 L2 정규화하면 내적만으로 유사도 계산 가능

### 11-9. hybrid search

image 점수와 caption 점수를 `alpha`로 가중 합산해 재정렬함.

```python
def hybrid_search(client, query_emb, alpha=0.5, k=3):
    img_hits = client.query_points(..., using='image').points
    cap_hits = client.query_points(..., using='caption').points
    # id별로 img·cap 점수 수집 후 alpha*img + (1-alpha)*cap 로 정렬
    ranked = sorted(score.items(), key=lambda x: alpha*x[1]['img'] + (1-alpha)*x[1]['cap'], reverse=True)
    return ranked[:k]
```

> 실무: alpha=1이면 순수 이미지 검색, alpha=0이면 순수 캡션 검색. 두 모달리티 강점을 가중 결합

## 고려사항 & 질문 모음

1. **CLIP vs ColPali 선택 기준**: CLIP은 이미지·텍스트를 단일 벡터로 임베딩해 가볍고 범용적. ColPali는 페이지를 통째로 multi-vector로 임베딩해 표·레이아웃 보존에 강하나 벡터 수가 폭증. 시각 요소가 많은 문서 검색은 ColPali, 일반 이미지·텍스트 검색은 CLIP이 적합.

2. **왜 Qdrant인가**: FAISS·Chroma는 한 컬렉션에 여러 named vector를 두기 어려움. Qdrant는 image·caption을 한 포인트에 함께 저장하고 벡터별 검색·필터·하이브리드를 지원해 멀티모달에 적합.

3. **캡션 임베딩 vs 이미지 임베딩**: 이미지 임베딩은 시각적 유사도, 캡션 임베딩은 의미적 유사도에 강함. hybrid search의 alpha로 둘을 조절하며, 질의 성격에 따라 최적 alpha가 달라짐.

4. **구조화 추출 vs 캡션**: 차트를 단순 캡션("매출 차트")으로 두면 수치 질의에 답할 수 없음. `ChartData`처럼 구조화 출력으로 받으면 값 비교·계산이 가능해짐. 단, 복원 오류 가능성이 있어 `sanity_check_chart` 같은 검증이 필요.

5. **한국어 멀티모달의 현실적 선택**: 영어 CLIP은 한국어 쿼리 성능이 낮음. 처음부터 다국어 학습은 비용이 크므로, distillation 기반 `clip-vit-base-patch32-ko` 같은 사전학습 모델을 쓰는 것이 실용적.

6. **Video RAG의 비용·정밀도 트레이드오프**: 프레임 샘플링 간격(`every_sec`)이 좁을수록 시각 정보는 촘촘하나 캡셔닝 VLM 호출 비용과 벡터 수가 증가. 음성 전사는 segment 타임스탬프로 검색 결과를 영상 구간에 정확히 연결 가능.
